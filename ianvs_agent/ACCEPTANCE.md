# Ianvs Agent 验证记录

本文区分本轮回归与既有真实模型实验。文件、子进程、Python 环境、Textual App/Pilot 和 stdio 通信检查使用真实组件。需要已有模型或特定实验记录的检查，通过明确的环境变量读取；缺少条件时报告 SKIP。

完整会话、模型请求、运行日志和本机路径保存在被忽略的 `workspace/` 或配置的 `state_root` 中。Git 中提供源码、测试入口和经过整理的结果说明，凭据与模型制品保留在本地。

## 2026-10-11 实用性与流畅度

本轮验证以下行为：

- Linux 长日志追加保留文件锁、持久化和异常恢复，正常追加不反复解析全部旧事件。外部修改、进程重启及不完整尾部重新检查；Windows 保持完整校验。
- Windows 与 WSL 分帧传输完整消息，全部片段收到后再发布状态。持续会话使用增量更新；连接中断后从后端正式记录恢复。
- 工具调用状态与运行、验证结果分别显示；长输出截断后保留运行身份及判定概要。
- 已失败、阻塞、取消或中断的任务有明确继续入口，沿用原目标、验收和累计用量。
- 频繁日志输出合并界面刷新，进度输出连续显示；原始日志和事件仍完整保存。
- 模型读取超时、部分响应断流及请求总超时按配置重试，保留每次尝试的原始分片和用量；认证、响应校验错误及取消维持明确结果。
- 周期摘要的可恢复网络失败保存为 deferred；符合模型窗口的 Plan 可以继续。同一历史不重复失败摘要，新增完整交互后重新评估。
- 服务报告超限且没有较早历史时继续缩减工具证据发送预览，保留完整结果引用；固定上下文仍超过窗口时明确失败。
- 目录读取产生正式工具错误后可继续任务；已经退出的旧所属进程不阻止下一次 Run；包清单检查采用实例运行环境。
- 创建时保存原始文件字节和来源版本。失效路径只接受同一 Example、完整目录后缀、唯一候选及创建摘要一致的来源；原 `task_spec` 和任务验收要求保留。
- 任务与新 Run 绑定同一目标版本；Context 持续读取正式来源，验证器检查完整声明、配置路径、指标实现及创建时已有制品身份。历史 Run 需要重新执行才能验证新版本。
- 环境准备在创建候选 venv 前离线解析依赖，保存具体失败计划与日志，保持既有环境；准备与安装计划同时核对文件版本和目录集合。
- 隐藏的日志页面重新显示后重新排版，末尾内容保持可见。

## 可重复执行的检查

在安装全部 Agent 依赖的 Linux 或 WSL 控制环境中，从仓库根目录执行：

```bash
python -m unittest discover -s ianvs_agent/tests -p 'test_*.py' -v
```

环境和补丁测试需要 `bubblewrap`、GNU `patch` 与可创建 venv 的 Python。将测试副本和实例放在 Linux 文件系统中；各测试支持的 `IANVS_*_TEST_ROOT` 或 `IANVS_*_ROOT` 参数见相应测试文件。PASS、FAIL 和 SKIP 分别保留，不把跳过项目计为通过。

真实 Run 验证检查使用 `IANVS_RUNTIME_EVIDENCE_ROOT`、`IANVS_RUNTIME_EVIDENCE_INSTANCE` 和 `IANVS_RUNTIME_EVIDENCE_RUN` 指定材料。Run 必须在原目标版本登记后真实执行，不能给旧 Run 补写目标身份。环境保留检查也读取明确指定的实例编号，正式材料保持只读。

Windows 前端检查使用安装了 `frontend-requirements.txt` 的 Windows Python。`test_tui_remote` 的真实会话检查还需要 `IANVS_TUI_BACKEND_CONFIG` 与 `IANVS_TUI_BACKEND_PYTHON`，指向独立的 WSL 验收状态和后端解释器。

真实 Provider 检查会请求模型并产生 Token 消耗：

```bash
python -m ianvs_agent.tests.check_provider_live --profile ark --profile glm
python -m ianvs_agent.tests.check_provider_live --profile ark --compact
```

模型凭据由后端环境变量提供。Provider 检查读取本地文档并完成真实 Tool Calling；它本身不证明 Example 已修复。

网络故障恢复检查通过本地真实 HTTP 连接重放已有方舟响应的 `raw_chunks`，不调用模型或构造成功答复。`IANVS_PROVIDER_CAPTURE_REQUEST` 指向包含流式工具调用的已完成 `attempt-*.json`；`IANVS_REPEATED_CONTEXT_CAPTURE_SESSION` 指向保存 CP-0007 的实际历史会话。证据缺失时相应用例保持 SKIP：

```bash
python -m unittest -v ianvs_agent.tests.test_provider_recovery ianvs_agent.tests.test_context_recovery
```

检查涵盖无响应头超时、部分流中断、总请求时限、重试次数、认证拒绝、响应校验、取消与记录写入错误。恢复检查证明请求与状态处理行为，Example 修复仍需真实执行及独立验证。

## 已有真实修复和代码修改实验

2026-10-10 的三项实验使用 `llm_simple_qa`、CPU 上的真实 `Qwen2.5-0.5B-Instruct` 和单条 QA 数据；Agent 请求配置为 `ark-code-latest`。每项实验包含一条可见用户任务，正式记录保留失败工具与中间尝试。

| 任务 | 首次独立验证通过耗时 | 输入 / 输出 / 合计 Token | 结果 |
| --- | --- | --- | --- |
| 修复错误 testenv 配置引用 | 315.51 秒 | 173195 / 5601 / 178796 | 原任务 acc=1.0，独立验证通过 |
| 修复 Python `generte` 调用错误 | 188.03 秒 | 58534 / 1319 / 59853 | 原任务 acc=1.0，独立验证通过 |
| 支持算法 YAML 配置 `max_new_tokens`，默认 512 | 291.92 秒 | 274900 / 6034 / 280934 | 默认配置下原任务 acc=1.0，独立验证通过 |

功能修改后另执行默认值、64、true、false、0、-1 六个配置行为检查，6/6 符合相应要求。64 Token 场景存在答案截断，未据此声称其质量与默认配置相同。这三项录像没有触发上下文压缩，也不构成一小时连续运行证明。

2026-10-09 的环境维护实验耗时 1705.94 秒，输入 141301、输出 3674、合计 144975 Token；9 次模型请求、7 次工具调用。使用已有缓存完成依赖操作后，原任务 acc=1.0，23 项独立检查通过。该记录说明该实例中的真实维护与复验过程，未覆盖所有 Example 的依赖组合。

同模型接入配置的 OpenCode 1.18.32 对比中，Windows 执行端首次原任务成功为 516.21 秒、488333 Token。Ianvs Agent 的 315.51 秒包含其独立验证，执行端为 WSL；两者停止计时条件和运行环境不同。该次观察可用于说明各自执行过程，不能推导一般性的速度或 Token 优势。

## 上下文与长期会话的证据

2026-10-10 的上下文检查包含 42 项控制逻辑检查及真实历史恢复。在任务累计输入达到 528023 Token 后，仍能发送下一次 Plan；该次真实请求输入 15571、输出 509 Token。实验将压缩周期参考量设置为 100000，产品默认值保持 500000。

周期压缩、窗口压缩和手动压缩都保留完整历史与正式任务。累计用量用于统计和压缩触发，不终止任务。单次模型窗口、请求超时、Runner 超时、用户取消和审批拒绝仍有各自的真实处理结果。
