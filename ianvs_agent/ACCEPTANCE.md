# Ianvs Agent 验证记录

本文区分本轮回归与既有真实模型实验。文件、子进程、Python 环境、Textual App/Pilot 和 stdio 通信检查使用真实组件。需要已有模型或特定实验记录的检查，通过明确的环境变量读取；缺少条件时报告 SKIP。

完整会话、模型请求、运行日志和本机路径保存在被忽略的 `workspace/` 或配置的 `state_root` 中。Git 中提供源码、测试入口和经过整理的结果说明，凭据与模型制品保留在本地。

## 2026-10-11 完整任务完成与正式来源读取

任务通过 `declare_completion_contract` 保存原用户要求、来源事件及逐版完成清单。成果类型为 `answer`、`environment`、`benchmark` 和 `code`，行动任务可以同时包含多项。已有要求不能由后续摘要或模型调用删除；明确的用户补充保存到正式记录后可以追加新版本。

- 纯问答在同一声明调用提供 `answer_text`，取得正式声明记录后返回答复。
- 环境成果需要当前任务、实例、环境代次与依赖文件版本一致的真实检查；有待执行的安装方案时保持待完成。
- 只有工具成功登记、`requires_install=true` 且具有正式 `plan_id` 和引用的安装计划进入待执行状态，失败计划与日志继续保存。安装成功且执行后检查通过，只清除最近登记并与 `apply.plan_id` 匹配的计划；Harness 按当前任务的正式工具记录重新计算待执行状态。
- 受控准备或安装通过后，以 `readiness.json` 保存不可覆盖的原批准检查范围、递归依赖文件版本、完整包版本、环境代次和解释器身份。后续 `inspect_environment` 始终包含原范围，清空参数不能缩减要求；同一工作进程使用 pip 分别解析原范围和本次增量要求。额外检查失败保留本次失败结果，原范围仍通过时保留已有 `ready`。`modified` 只有在本次完整检查通过、原范围及全部身份一致时才恢复；原范围记录损坏会保存 `modified` 和错误引用，缺少可信范围的旧 `modified` 环境需要受控准备或安装。
- 评测成果需要当前任务最新 Run 的独立验证，核对原目标版本、当前源码及运行状态。环境准备成功只更新环境子项。
- 代码成果需要当前任务仍有效的 Diff，以及通过 `completion_requirement_id` 关联的真实功能检查。检查保存命令、退出结果、源码版本、环境代次、依赖身份及完整日志。
- 行动任务在全部正式证据满足后，由 Observe 判断整项用户要求是否完成。证据缺失、包版本变化、后续功能检查失败或撤销全部修改时继续推进未完成项目。
- 会话恢复和上下文压缩持续保留原目标、清单及正式证据。显式继续任务时核查当前状态；历史成功记录与当前待完成要求分别显示。
- 每次 Plan 和 Observe 请求在历史材料之后附加当前任务的 `completion_progress`，包括 `task_id`、证据适用范围、逐项状态、证据引用和 `pending_reason`。待完成原因直接说明需要取得的当前环境检查、Run 或功能检查；历史 `verification.passed` 仅提供背景。模型填写的成果说明与 `next_goal` 不能替代程序检查。
- `read_evidence` 可读取当前任务正式原目标 `bindings` 精确登记的文本对象，核对创建摘要并按原编码分页返回；未绑定对象、其他实例独有对象、内容损坏及二进制被拒绝。当前任务经验证的完成清单也可通过其精确引用读取。

## 此前的实用性与流畅度检查

本轮验证以下行为：

- Linux 长日志追加保留文件锁、持久化和异常恢复，正常追加不反复解析全部旧事件。外部修改、进程重启及不完整尾部重新检查；Windows 保持完整校验。
- Windows 与 WSL 分帧传输完整消息，全部片段收到后再发布状态。持续会话使用增量更新；连接中断后从后端正式记录恢复。
- 工具调用状态与运行、验证结果分别显示；长输出截断后保留运行身份及判定概要。
- 已失败、阻塞、取消或中断的任务有明确继续入口，沿用原目标、验收和累计用量。
- 频繁日志输出合并界面刷新，进度输出连续显示；原始日志和事件仍完整保存。
- 模型读取超时、部分响应断流及请求总超时按配置重试，保留每次尝试的原始分片和用量；认证、响应校验错误及取消维持明确结果。
- 周期摘要的可恢复网络失败保存为 deferred；符合模型窗口的 Plan 可以继续。同一历史不重复失败摘要，新增完整交互后重新评估。
- 服务报告超限且没有较早历史时继续缩减工具证据发送预览，保留完整结果引用；固定上下文仍超过窗口时明确失败。
- 目录读取产生正式工具错误后可继续任务；已经退出的旧所属进程不阻止下一次 Run；包清单检查采用实例运行环境。
- 创建时保存原始文件字节和来源版本。失效路径只接受同一 Example、完整目录后缀、唯一候选及创建摘要一致的来源；原 `task_spec` 和任务验收要求保留。
- 任务与新 Run 绑定同一目标版本；Context 持续读取正式来源，验证器检查完整声明、配置路径、指标实现及创建时已有制品身份。历史 Run 需要重新执行才能验证新版本。
- 环境准备在创建候选 venv 前离线解析依赖，保存具体失败计划与日志，保持既有环境；准备与安装计划同时核对文件版本和目录集合。
- 隐藏的日志页面重新显示后重新排版，末尾内容保持可见。
